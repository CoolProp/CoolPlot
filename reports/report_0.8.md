# Report 0.8: documentation (branch chp/0.8)

Scope (docs/contributing/v1_plan.md, 0.8): Sphinx with MyST, numpydoc with a
linter, sphinx-gallery from examples/, Read the Docs, the Diataxis structure, the
generated reference, the gallery, the changelog in Keep-a-Changelog form with the
upgrade guide, a picture in the README.

## What changed

* `docs/` is a Sphinx site: MyST Markdown pages, the pydata theme, numpydoc, the
  API reference generated by autosummary (one page per module, 54 pages), tables
  generated from the package at build time (`docs/_tables.py`: quantities and
  aliases, diagram types and families, limit presets, unit systems, settings
  presets, themes), the gallery built by sphinx-gallery from `examples/` (every
  example run at build time; a scraper picks up the SVG and PNG files the examples
  write), the changelog included from `CHANGELOG.md`.
* Diataxis: `getting_started`; tutorials (a first chart, a heat pump from
  measurements, an air handling unit, figures for a paper); how-to (units,
  isolines, labels, cycles, blends, PDF and print, themes, embedding, web and
  background, troubleshooting); explanation (what a change costs, colours, label
  placement, numerics, not supported, the pipeline); reference (API, tables,
  contracts); gallery; changelog; upgrade guide; contributing (rules, writing a
  backend, the design document, the plan, the review, the review checklist).
  `docs/user_guide.md` and `docs/styling.md` are split into those pages;
  `backends.md`, `architecture.md`, `contracts.md`, `v1_plan.md`, `v1_review.md`
  moved.
* 108 docstrings added to public methods and properties; the build checks for a
  missing one (`numpydoc_validation_checks = {"GL08"}`) and `sphinx-build -W`
  fails on it.
* `coolplot.engine.plan` is the function; the module is `coolplot.engine.planning`
  (the two shared one name, which the reference cannot have).
* README with the picture (`docs/_static/R290_ph.png`), engineering vocabulary on
  the first screen, pointers to the documentation.
* `CHANGELOG.md` in Keep-a-Changelog form (Unreleased with 0.8.0 ... 0.2.0, then
  0.1.x); `docs/upgrade.md` with the 0.6 to 0.7, 0.4 to 0.5 and legacy tables.
* `.readthedocs.yaml`, `docs/requirements.txt`, the `docs` job in the tests
  workflow (`sphinx-build -W --keep-going`), `make docs`.
* `docs/contributing/review_checklist.md`: the 24 findings of the documentation
  review and how each was closed.

## Decisions taken

* The numpydoc check enforces only "every public object has a docstring"
  (GL08); the section checks (Parameters, Returns) are not enforced, because the
  docstrings describe what matters in prose and converting 160 of them to
  numpydoc sections is churn without a reader.
* The reference tables are generated at build time rather than written by hand,
  so they cannot drift; `docs/reference/tables.md` is not committed.
* Examples write their files into `examples/` when the gallery runs them; those
  files are ignored by git.
* The design document, the plan and the review stay in the repository under
  contributing as history pages; contributing itself has only the rules.

## Review

The adversarial review ran every code block of the documentation against the
package and found: the tutorial on measured states used R410A with pressures
that belong to propane (its own code gave a COP of 0.77); `save("chart.svg")`
and `save("chart.html")` were documented as working without matplotlib but
went through it (`Chart.save` now chooses the writer by the extension, with a
test); the gallery scraper attributed files of other examples to the current
one (now one claim per file and build, and the old outputs are removed before
the build); the upgrade table named a method that never existed and missed
the other deprecated names; the review checklist claimed four backends on
pages that named two or three; stale paths to the moved documents; a
troubleshooting entry that cannot occur. All fixed in "Review fixes for the
documentation". Noted, not changed: the docs job and Read the Docs pin
CoolProp 8.0.0 now, like the test matrix.
